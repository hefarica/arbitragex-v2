## 1. No-hardcode rules applied

Rules enforced during this audit:
- Productive values must trace back to one of the 8 allowed sources.
- Canonical protocol constants (router addresses) may remain in `shared-rs/src/chains.rs` with byte-asserting tests.
- Dev-only defaults (e.g. `${ARBX_ADMIN_TOKEN:-dev_admin_token_change_me}`) must either fail-closed in non-dev environments or be removed entirely.
- Placeholder `REPLACE_ME_*` in `.env.example` is allowed because it's explicit documentation.

Grep pipelines executed:
- Addresses: `0x[0-9a-fA-F]{40}` across `**/*.{rs,ts,tsx,toml,yml,yaml,json,sql,sh}`.
- Endpoints: `https?://[a-zA-Z0-9.-]+\.[a-zA-Z]{2,}` across source + infra files.
- Dev defaults: `:-[a-zA-Z0-9_]+}`, `REPLACE_ME`, `change_me`, `dev_admin`, `dev_edge` across `.env*`, `.yml`, `.sh`.

## 5. Validation mechanisms

| Datum class | Validation |
|-------------|-----------|
| URL | parse + scheme check + reachability probe at intake |
| EVM address | `0x` + 40 hex + EIP-55 checksum accepted, lower-cased for storage |
| Private key | `secp256k1` parse, derive address, assert zero-balance for phase 4 |
| Token (opaque bytes) | min entropy check (base64 length â‰¥ target) |
| Chain ID | int in {1, 10, 137, 42161, 8453, â€¦} â€” operator-enabled set |
| RPC | `eth_chainId` probe matches expected chain |
| Relay auth | `X-Flashbots-Signature` / header-auth probe against /v1/* |
| CF API token | GET `/user/tokens/verify` |
| Slack webhook | HEAD request; expect `405` with `Allow: POST` |
| PD key | POST test event with `action: trigger` + `dedup_key` then resolve |
| age pubkey | `age-keygen` format parse |
| B2 bucket creds | `rclone lsd` probe |
| scoring weights | non-negative + sum to 1.0 Â± 0.001 |
| thresholds | bounded ranges defined per-field in config schema |

Every validator returns `{ok: true}` or `{ok: false, reason: "...", retry_after?: ...}` that the onboarding UI renders next to the field.
