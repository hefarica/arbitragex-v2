# Smart contract security and EVM simulation for MEV/arbitrage (2024-2026 state of the art)

## 1. SIMULATION: REVM vs Anvil vs Tenderly vs custom forks

The canonical production pattern in 2024-2026 is **REVM in-process for the hot path, Anvil/Tenderly for debugging and bundle verification only** ([Solid Quant: Why everyone should use REVM](https://medium.com/@solidquant/why-i-think-everyone-should-use-revm-rust-evm-art-of-mempool-watching-part-2-c67308d5cf03), [Dwellir: MEV bot infrastructure](https://www.dwellir.com/blog/mev-arbitrage-bot-infrastructure)).

Hard benchmark numbers exist from the [hotpath.rs REVM/Anvil/Alloy tutorial](https://hotpath.rs/blog/revm-alloy-anvil-arbitrage) (100 quote simulations of a 2-pool UniswapV3 arb, 0-0.1 ETH sizes):
- Naive `eth_call`: ~89ms on a local full node, ~4.4s via Alchemy (100 RPC round-trips).
- Anvil fork (lazy on-demand fetch): ~120ms local / ~868ms remote (36 RPC calls).
- REVM + `CacheDB<AlloyDB>`: ~80ms local / ~1010ms remote (33 RPC calls).
- REVM + bytecode caching (`cacache`, bytecode never changes) + account mocking (zero balance/nonce) + storage-slot mocking (fake huge balances via `insert_mapping_storage_slot` on keccak256(mapping slot,key), found with `slither-read-storage`) + custom minimal quoter that reverts with `amount0Delta/amount1Delta` encoded in the revert data: **~19ms local / ~405ms remote, only 10 RPC calls — ~10x speedup and ~90% RPC-call reduction**; gas per quote dropped ~90,966 from ~123k. The custom-quoter revert trick works on V3 clones where official QuoterV2 does not.
- `evm.transact()` for non-persisting probes vs `transact_commit()` for stateful multi-leg sequences.

Tenderly cloud forks ([Tenderly Forks](https://tenderly.co/blog/tenderly-forks-one-click-development-testnet/)) are excellent for visualization and state manipulation but add network latency + per-call cost — disqualified for hot paths. Anvil is best for multi-tx bundle simulation ([Degencode: multi-transaction bundle simulation with Anvil](https://www.degencode.com/p/multi-transaction-bundle-simulation-with-anvil)). [foundry-rs/op-revm](https://github.com/foundry-rs/op-revm) shows the low-level programmatic EVM execution API. Production searcher stacks: [rusty-sando](https://github.com/mouseless0x/rusty-sando) (Rust+Huff multi-meat sandwich bot) and [paradigmxyz/artemis](https://github.com/paradigmxyz/artemis) (event-driven modular MEV bot framework; [usage guide](https://mteam.space/posts/how-to-use-the-artemis-mev-framework/)).

**Defensive corollary for a trading system:** simulate every candidate bundle against the pending block state (and with `stateOverride` for adversarial scenarios), capture revert reasons as first-class telemetry, and treat simulation-vs-onchain divergence > epsilon as a kill signal.

## 2. FORMAL VERIFICATION in production

- **Certora Prover went open source in 2025** ([announcement](https://www.certora.com/blog/certora-goes-open-source)) — rule-based bytecode-level verification proving all states within a formalized ruleset; production specs/published reports are browsable at [github.com/Certora/SecurityReports](https://github.com/Certora/SecurityReports). Certora also published v4-hook-specific best practices including the "pool key spoofing" attack class ([Certora on v4 hooks](https://www.certora.com/blog/best-practices-writing-secure-uniswap-v4-hooks)).
- **Halmos** (a16z) turns existing Foundry unit tests into symbolic proofs — [stateful invariant testing with Halmos](https://a16zcrypto.com/posts/article/implementing-stateful-invariant-testing-with-halmos/) shows checking invariants over the whole input space vs fuzzers' concrete values.
- **Echidna** (Trail of Bits, [github.com/crytic/echidna](https://github.com/crytic/echidna)) added a symbolic-execution verification mode — convergence of fuzzing and symexec ([Grieco's writeup](https://gustavo-grieco.github.io/blog/echidna-symexec/)); uses hevm internally ([MixBytes](https://mixbytes.io/blog/fuzzing-smart-contracts-practical-aspects-echidna)). [hevm docs](https://hevm.dev/when-to-use.html) note symexec beats fuzzing for rare/deliberately hidden bugs.
- **Foundry invariant testing** (fuzz/invariant harnesses with handler contracts) is now table stakes in audit contests (Code4rena/Sherlock). Recon's [Halmos guide](https://getrecon.xyz/blog/halmos-symbolic-execution-guide) contrasts the tools.
- Production relevance to MEV: arbitrage/router/executor contracts should get invariant specs like "netTopologicalYield >= 0 in every reachable state after gas" and "flash loan always repaid in same tx" (atomicity), since these are exactly the properties that fail economically.

## 3. FLASH LOAN attack surface (and legitimate use)

Attack pattern: borrow huge capital atomically -> manipulate AMM spot/oracle -> extract from lending/liquidation/governance logic -> repay, all in one tx ([Cyfrin full guide](https://www.cyfrin.io/blog/price-oracle-manipulation-attacks-with-examples), [smartcontractshacking.com](https://smartcontractshacking.com/attacks/flash-loans-attacks), [CertiK Oracle Wars](https://www.certik.com/blog/oracle-wars-the-rise-of-price-manipulation-attacks) — lineage back to bZx ~$350k in 2020). Academic tooling: static analysis of flash-loan vulnerability patterns ([arXiv 2411.01230](https://arxiv.org/html/2411.01230v2)); "LeiShen" detection over the first 14.5M Ethereum blocks ([paper](https://www.semanticscholar.org/paper/Detecting-Flash-Loan-Based-Attacks-in-Ethereum-Xia-Huang/654b2774f072c5ad337bc13fad6f0d3a113515a6)). 2024 exploit breakdown by root cause: [Three Sigma](https://threesigma.xyz/blog/exploit/2024-defi-exploits-top-vulnerabilities).
Defenses: never read raw DEX spot as an oracle; TWAP/median aggregation; multi-source validation; real-time pre-execution monitoring ([Guardrail](https://www.guardrail.ai/common-attack-vectors/price-oracle-manipulation)); flash-loan-fee economics (attacker must pay fee + slippage, so thin manipulations are unprofitable).
**Legitimate use** (ArbitrageX context): atomic, capital-free execution of multi-leg routes — provider selection matters: Balancer vaults historically 0 fee, Aave v3 0.05%, Uniswap V3 flash swaps charge only the pool fee on the borrowed leg; the correct math treats the flash fee as part of route cost C_R(x) and uses flash only when inventory financing cost > flash fee.

## 4. ORACLE SECURITY: TWAP vs spot vs Chainlink OCR

- **OWASP Smart Contract Top 10, 2026 edition, SC03 Price Oracle Manipulation** ([link](https://github.com/OWASP/www-project-smart-contract-top-10/blob/main/2026/en/src/SC03-price-oracle-manipulation.md)) enumerates current vectors: same-block spot manipulation via flash loans and JIT liquidity, TWAP manipulation over short windows/low-liquidity periods.
- **Chainlink OCR 2.0**: medianized aggregation from independent node operators off-chain; resistant to single-source manipulation ([Chainlink education hub](https://chain.link/education-hub/market-manipulation-vs-oracle-exploits); [event-enriched detection paper, ACM 3817054](https://dl.acm.org/doi/10.1145/3817054) confirms OCR2 design; [Galaxy research overview](https://www.galaxy.com/insights/research/chainlink-oracles-ccip-price-feeds)).
- **TWAP is a non-solution arms race**: lengthening the window buys manipulation resistance at the price of staleness ([comparative analysis](https://uk.investing.com/news/cryptocurrency-news/twap-oracles-vs-chainlink-price-feeds-a-comparative-analysis-2599057)); academic proposal for manipulation-resistant gas-efficient oracles in [arXiv 2410.07893](https://arxiv.org/html/2410.07893v2); [Nethermind breakdown](https://www.nethermind.io/blog/price-manipulation-attacks-in-defi-all-you-need-to-know).
- **Stale-data windows (production best practice)**: staleness threshold must be per-feed, derived from that feed's heartbeat + buffer, never a global constant — a real Code4rena bug used one heartbeat for all feeds ([noya finding](https://github.com/code-423n4/2024-04-noya-findings/issues/215)); validate `updatedAt`, `answer > 0`, `roundId != 0`, `answeredInRound >= roundId` ([Cyfrin Chainlink attacks guide](https://medium.com/cyfrin/chainlink-oracle-defi-attacks-93b6cb6541bf), [RareSkills](https://rareskills.io/post/chainlink-price-feed-contract), [stackexchange](https://ethereum.stackexchange.com/questions/154261/chainlink-stale-data-latestrounddata-guide)); on L2s, gate on the sequencer uptime feed; on staleness, revert/fallback rather than proceed into liquidations.

## 5. BRIDGE SECURITY

Dominant failure modes 2024-2026: private-key/validator compromise, faulty message verification, unsafe upgradability, wrong finality assumptions ([Chainlink: seven bridge vulnerabilities](https://chain.link/education-hub/cross-chain-bridge-vulnerabilities); [systematic survey](https://www.researchgate.net/publication/384462541); [ACM security analysis](https://dl.acm.org/doi/10.1145/3727648.3727685); [Sherlock 2026 threat models](https://sherlock.xyz/post/cross-chain-security-in-2026)). Scale: bridges ~69% of DeFi funds stolen over the recent two-year window ([Hacken/Chainalysis](https://hacken.io/discover/cross-chain-interoperability-report/)); in 2025 bridge exploit losses declined but bridges laundered >$1.5B of stolen funds ([Spark bridge data](https://www.spark.money/tools/bridge-security-comparison)). Research direction: failure containment instead of binary up/down trust ([arXiv 2601.12434](https://arxiv.org/html/2601.12434v1)); **liquidity poisoning attacks on multihop bridges** — sequence-dependent arbitrage exploiting temporal gaps between hop confirmations ([IMDEA paper](https://dspace.networks.imdea.org/bitstream/handle/20.500.12761/2037/CCW_Paper.pdf?sequence=1)). Verification patterns: cross-chain price-consistency checks ([Zealynx checklist](https://www.zealynx.io/research/smart-contracts/cross-chain-bridge-security-checklist)), message-level signature/quorum validation, rate limits, per-route TVL caps.

## 6. ECONOMIC SECURITY: game theory + mechanism design

- Foundational formalization: [Price of MEV: Towards a Game Theoretical Approach (arXiv 2208.13464)](https://arxiv.org/html/2208.13464v1) — models MEV games and ordering-mechanism externalities.
- Transaction fee mechanism design post-MEV: [Roughgarden/Bahrani et al.](https://timroughgarden.org/papers/eobp3.pdf).
- Order-flow auctions: Flashbots' OFA analysis ([Order Flow, Auctions and Centralisation II](https://writings.flashbots.net/order-flow-auctions-and-centralisation-II)); MEV ACE programmable OFA ([paper](https://www.researchgate.net/publication/408229343_Enabling_Decentralized_Programmable_Order_Flow_Auctions_for_MEV_Mitigation_in_DeFi)); FRP-34 asks whether backrun-only auctions actually protect users ([Flashbots collective](https://collective.flashbots.net/tag/mev-share)).
- **Empirics 2025 (EigenPhi via Cointelegraph)**: sandwich extraction fell sharply while monthly DEX volume rose ~$65B -> $100B+; Ethereum sandwiches drained ~$40M with **average profit per attack ~$3 and only six attackers above $10K total** ([Cointelegraph/EigenPhi](https://www.tradingview.com/news/cointelegraph:fa12ba092094b:0-exclusive-data-from-eigenphi-reveals-that-sandwich-attacks-on-ethereum-have-waned/)) — extreme concentration; arbitrage dominates MEV by tx count ($3.37M profit/30d, Sep 2025; [Arkham guide](https://info.arkm.com/research/beginners-guide-to-mev)).
- **Cross-chain arb (TU Munich, ACM POMACS 2025)**: year-long measurement across 9 chains; cross-chain arb fosters vertical integration and centralizes sequencing + economic power ([ACM](https://dl.acm.org/doi/10.1145/3771566), [arXiv 2501.17335](https://arxiv.org/html/2501.17335v2), [detection methodology on Flashbots](https://collective.flashbots.net/t/detecting-cross-chain-arbitrages-in-the-wild/5107), [Allium pipeline](https://www.allium.so/blog/cross-chain-arbitrage-and-mev-tu-munich-research-built-on-allium-data-2/)). Winning bots skip bridges entirely using pre-positioned inventory ([CoW on cross-chain MEV](https://cow.fi/learn/cross-chain-mev-how-bots-extract-value-when-you-move-between-chains)).
- **Liquidation economics shifted in 2025**: Aave V4 dynamic liquidations = implicit Dutch auction (reward escalates over time; ~295k liquidations/$3.3B processed historically; [Aave blog](https://aave.com/blog/aave-v4-liquidations), [Stani's thread](https://x.com/StaniKulechov/status/2029881317429551163)); Aave SVR (Secure Value Recovery, builder-integrated liquidations) recaptured **$16.7M+ MEV** on Ethereum and is expanding to Arbitrum/Base ([news](https://cryptonews.net/news/defi/32623126/)); Euler's forum analysis of MEV in Dutch-auction liquidations ([link](https://forum.euler.finance/t/mev-in-euler-dutch-auctions/1012)).
- **ML/RL in the loop**: reinforcement learning for MEV extraction on Polygon ([arXiv 2510.14642](https://arxiv.org/html/2510.14642v1)); ML analysis of bidding behavior in Flashbots auctions ([IACR eprint 2023/1281](https://eprint.iacr.org/2023/1281)).

## 7. NEW 2025-2026 VECTORS AND DEFENSES

- **Bybit Feb 2025, ~$1.5B — largest ever**: supply-chain compromise of the Safe{Wallet} UI (Lazarus) ([Halborn year-in-review](https://www.halborn.com/blog/post/year-in-review-the-biggest-defi-hacks-of-2025)). Lesson: interface/key-management supply chains, not contract bugs, now dominate loss size.
- **Uniswap v4 hooks (launched Jan 2025) as a new attack surface**: Cork Protocol, May 28 2025, $11M — chained hook weaknesses ending in an access-control failure ([Dedaub forensics](https://dedaub.com/blog/the-11m-cork-protocol-hack-a-critical-lesson-in-uniswap-v4-hook-security/)); risk catalogs from [Hacken](https://hacken.io/discover/auditing-uniswap-v4-hooks/), [QuillAudits](https://www.quillaudits.com/research/uniswap-development/uniswap-v4/uniswap-v4-hooks-and-security), [CertiK](https://www.certik.com/blog/uniswap-v4-hooks-security-considerations), [BlockSec](https://blocksec.com/blog/thorns-in-the-rose-exploring-security-risks-in-uniswap-v4-s-novel-hook-mechanism), [official framework](https://developers.uniswap.org/docs/protocols/v4/security).
- **JIT liquidity as MEV**: mint concentrated position immediately before a large swap, burn right after (mint->swap->burn pattern) ([IACR eprint 2023/973](https://eprint.iacr.org/2023/973), [Uniswap's view](https://blog.uniswap.org/jit-liquidity), [detection heuristics](https://medium.com/@alexanderzaidelson/dissecting-the-jit-liquidity-attack-b283504e0de7)); v4 hooks (burn delays, dynamic fees) are the discussed defense ([analysis](https://academy.exmon.pro/future-of-liquidity-uniswap-v4-hooks-vs-jit-mev-attacks)).
- **Protocol-layer changes**: EIP-7732 ePBS selected as Glamsterdam headliner (target Q3 2026) + FOCIL inclusion lists (EIP-7805) — moves PBS into consensus, kills the proposer "free option", reshapes builder competition ([EIP-7732](https://eips.ethereum.org/EIPS/eip-7732), [Sigma Prime Glamsterdam preferences](https://sigmaprime.io/blog/glamsterdam-eip-preferences/), [Flashbots MEV perspective](https://collective.flashbots.net/t/an-mev-perspective-on-glamsterdam/5116), [arXiv analysis](https://arxiv.org/html/2506.18189v1), [Shutter critique](https://blog.shutter.network/shutters-perspective-on-glamsterdam-and-a-cryptographic-fix-for-epbss-free-option-problem/)).
- **TEEs and private orderflow**: Flashbots SGX builder/OFA lineage and SUAVE coprocessor ([eco.com overview](https://eco.com/support/en/articles/14796360-tees-in-blockchain-use-cases-and-projects), [The Future of MEV is SUAVE](https://collective.flashbots.net/t/the-future-of-mev-is-suave/762), [EigenPhi's candid post-mortem: TEE builder without private orderflow wasn't competitive](https://eigenphi.substack.com/p/mev-space-3-tee)); sealed-bid TEE auctions formalized in 2025 ([ACM](https://dl.acm.org/doi/10.1145/3733815.3764043)); benchmark of private protection RPCs (Merkle, Blink, Flashbots Protect) in [arXiv 2505.19708](https://arxiv.org/html/2505.19708v1). MEV-Share remains the live programmable-privacy OFA ([docs](https://docs.flashbots.net/flashbots-mev-share/introduction), [node open-sourced](https://writings.flashbots.net/open-sourcing-flashbots-mev-share-node), [searcher guide](https://writings.flashbots.net/searching-on-mev-share)).
- **2026 momentum**: $840M lost in first five months of 2026 across 50+ incidents (+70% YoY; [AltFINS](https://altfins.com/blog/defi-hacks-2026/)); large 2026 incidents include KelpDAO ($292M) and Drift ($285M) ([DefiMon](https://defimon.xyz/blog/top-10-defi-hacks-2026)); ENISA flags AI-assisted social engineering ([ENISA 2025](https://www.enisa.europa.eu/sites/default/files/2026-01/ENISA%2520Threat%2520Landscape%25202025_v1.2.pdf)); the "MEV spam wall" and MEV trilemma frame current strategy constraints ([Extropy Q4 2025 review](https://academy.extropy.io/pages/articles/mev-crosschain-analysis-2025.html)); Flashbots argues MEV is now the dominant limit to blockchain scaling ([post](https://writings.flashbots.net/mev-and-the-Scaling)).
